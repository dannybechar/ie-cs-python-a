# Grade 7 / Python A — Annual Strategy

Source of truth: [`ministry-source/python-a.pdf`](ministry-source/python-a.pdf).
Per-unit detail (official scope, meeting breakdown, exit criteria, depth
boundary, enrichment) lives in each unit's own `unit-strategy.md` —
see [`../course-map.md`](../course-map.md) for the full list.

## 1. Foundational Decisions

- Source of authority: Ministry of Education documents.
- Rigid scope: **60 academic hours of 45 minutes**.
- Operating structure: **30 double meetings of 90 minutes**.
- Official split: **44 practical hours + 16 theory hours**.
- All 9 Python A chapters are Core.
- Default double meeting: **45 min knowledge delivery + 45 min lab**.
- Where a unit has more practical hours than theory hours, the remaining
  meetings are **Lab + Lab**.
- Deadline: all units are taught before the Ministry's Python A exam,
  estimated for May 2027 (circular תשפ"ז).
- Unit 0 (environment setup) is one school-added meeting outside the 60
  hours, so the year has 31 meetings.
- Time and topic coverage are tracked in [`../course-map.md`](../course-map.md)
  (time budget, schedule, open gaps) and in each unit's `unit-strategy.md`
  ("Official topics and hours").
- Enrichment does not receive separate hours.
- Old Python C serves only as an **Extension Bank** for strong students.
- Do not systematically pre-teach core topics of follow-on programs purely
  for enrichment.
- `Self.py` / `Next.py` are not a planning basis; they may be used in the
  future only as a targeted pedagogical reference.

## 3. Pedagogical Phases

### Phase 1 – Foundation – 12h
Units 1–3: First program → Turtle → Variables
(preceded by Unit 0, a school-added setup lab outside the 60 hours:
install, check and save in the working environment)

### Phase 2 – Control Flow – 14h
Units 4–5: Conditions → Loops

### Phase 3 – Problem Solving – 14h
Units 6–7: Strings → Algorithmic Patterns

### Phase 4 – Modularity & Interaction – 20h
Units 8–9: Functions → Event-Driven Programs

The four-phase split is internal pedagogical organization and does not
change the order or hours of the official program.

## 4. Default Lesson Pattern

**First 45 minutes – Knowledge / Instruction** (not one continuous lecture):
1. Hook / problem
2. Short explanation
3. Live code/demo
4. Predict before run
5. Guided micro-practice
6. Transition to lab

**Second 45 minutes – Lab / Practice**:
1. Run starter
2. Read
3. Predict
4. Modify
5. Test
6. Debug
7. Explain
8. Save / submit

In units with more practical hours, additional meetings are Lab + Lab.

## 5. Assessment Strategy

**Formative** — at the end of almost every lab: a short micro-task, output
prediction/tracing, explanation of one code fragment, a practical checkpoint.

**Phase checkpoints**:
- After Unit 3: Foundation checkpoint.
- After Unit 5: Control Flow checkpoint.
- After Unit 7: Problem Solving checkpoint.
- Unit 9: integrated final practical task/project.

Checkpoints are embedded inside lab hours, with no extra hours.

**Ministry exam habits (מפמ"ר)** to build across the year: tracing, code
completion, explaining what code does, writing a solution, working with
printed reference material — not relying on syntax memorization alone.

## 6. Enrichment Policy

- Enrichment only after Core mastery.
- No extra dedicated hours.
- Prefer harder problems using the same concepts.
- Python C is an Extension Bank, not an alternative curriculum.
- Avoid advancing major future-program core topics solely for differentiation.
- Especially suitable enrichment zones: Turtle challenges, loop/pattern
  challenges, algorithmic problem solving, modular decomposition, richer
  event-driven games.

## 7. Year Exit Profile

At the end of Grade 7, a student should be able to:

1. Work independently with a Python file/project.
2. Read, modify, run, debug and save code.
3. Use output, comments and clear structure.
4. Use variables, input/output and basic arithmetic.
5. Write and trace conditions.
6. Write and trace bounded and conditional repetition.
7. Work with strings using indexing, slicing and key operations.
8. Recognize and use counter/accumulator/min/max/random patterns.
9. Write and call functions with parameters that do not return values.
10. Understand local/global scope at the required level.
11. Build a simple event-driven interactive program with mouse/keyboard events.
12. Explain what code does, predict output and solve practical programming problems.

## 8. Final Summary

**Grade 7 = Python A, 60 academic hours**

- 30 double lessons × 90 minutes.
- 16 theory blocks + 44 practical blocks.
- 9 official Core units.
- Default: Knowledge 45 min → Lab 45 min.
- Practical-heavy units continue with Lab + Lab sessions.
- Assessment is embedded in the practical allocation.
- Python C is enrichment only.
- No systematic acceleration into future program content.
- The year develops through:
  **Foundation → Control Flow → Problem Solving → Modularity & Interaction**.
