# Audit: Unit 9 (event-driven programming) against the ministry Classroom program

Audited 2026-11-13. Read-only audit; no repo content was changed.

## Verdict

1. Unit 9 is richer than the folder (540 min against one ministry meeting, 20, plus exam prep) and matches python-a.pdf p.18-19 in goals and hours (12 h = 4 T + 8 P); every page citation checks out.
2. The one real risk is style: the folder, the exam aid (`materials-m20-5-7a9d0a.md`) and the folder's exam-style question (`materials-m19-1-b8b334.md` slide 22) all use the object style (`wn = turtle.Screen()`, `player = turtle.Turtle()`, `wn.onclick`, `wn.onkeypress`, `turtle.mainloop()`); the repo teaches only module-level calls (`turtle.onclick`, `turtle.onscreenclick`, `turtle.onkey`, `turtle.done()`), a documented choice that leaves students unable to read the exam code.
3. `ontimer`/animation (9.5) is not in folder meeting 20 or in the 20.5 sheet, but python-a.pdf p.18-19 requires animation with a wait/timer (3 h), so it stays; the folder's own animation (pong, 20.4) is a `while True` loop with `screen.update()`, not a timer.
4. Repo-only or inconsistent items: `not` is used in 9.2, 9.4, 9.5 although Unit 4 says it is not taught; the exam question needs `%` and `+=`; the "Python C enrichment" section lists "timer-oriented behavior" as enrichment although 9.5 teaches it as core.
5. The folder offers six reusable tasks (20.2 digits, 20.3 painter tasks 1-6, 20.4 pong plus true/false, m19 slide 22) that fit Unit 9 by swapping existing challenge slots; no minute is added. Decks are image-only, so deck text could not be compared by machine.

Authority used: folder = content, python-a.pdf = hours. Extracts are under `docs/ministry-program/extracts/`; folder numbers are authoritative. No file for "projects leading to the programming festival" exists in the extracts: the only mention is the last line of `classwork-m20-4-f13316.md` ("תוכלו לשתף את המשחק בתחרויות ופסטיבלים"); the folder has no 20.6 or project component.
