# Units: layout and rules

[Table of contents](../CONTENTS.md) · [Repository home](../README.md) · [Standards](../docs/standards/README.md)

One folder per unit, lower case: `u<N>-<name>/`, in teaching order (Unit 0 is the school-added Environment Setup).

```
units/u<N>-<name>/
  README.md              unit entry page: links to everything in the unit
  background-paper.md    teacher's technical and pedagogical background (not yet added for any unit)
  unit-plan.md           lesson sequence, minutes, status
  unit-strategy.md       the unit's official scope and meeting breakdown (kept from before the restructure)
  lessons/
    L<NN>-<slug>.md      the lesson page: the Hebrew student lab brief (source of truth)
    L<NN>-<slug>.html    generated one-file slide deck of that page
    L<NN>-<slug>/        slides-he.pdf (NotebookLM deck), printable lab sheets, exit check
  exercises/             student starter code (*_Starter.py) and extra-practice packs
  assessment/            student-facing test sheets (Unit 2 so far)
  teacher/               TEACHER-ONLY: lesson notes, reference solutions, answer keys, run of show
```

`NN` is the meeting number inside the unit (Unit 4.2 is `L02`). Unit 2 also has `L04`, the addendum session, which is outside the three official meetings.
There is no `feedback/` folder: external reviews are kept in [`docs/reviews/`](../docs/reviews/README.md). There is no `optional-java/` folder (this is a Python course).

## Rules

- **The background paper comes first.** Write or add it before drafting a unit's lessons, and link it from the unit plan, the entry page and `CONTENTS.md`. None exists yet; the entry pages say so and carry no dead links. Background papers are teacher-developed, not official publications: record version and date at the top.
- **Teacher-only files stay in `teacher/`.** Never put answers, solutions or marking notes in `lessons/`, `exercises/` or `assessment/`.
- **Markdown is the source of truth for a lesson page.** The `.html` deck is generated by [`tools/lesson-decks/build_decks.py`](../tools/lesson-decks/README.md); edit the Markdown and rebuild, never edit the HTML by hand.
- Each lesson follows the standards in [`docs/standards/`](../docs/standards/README.md): naming rule, Ministry precedence, minute budget, and the rule that every new idea is followed by a student action.
- Whenever a unit gains or changes material, update its entry page, its `unit-plan.md` and its row in [`CONTENTS.md`](../CONTENTS.md).
- Moves use `git mv` so history is kept; links are fixed in the same commit.

## Checks before you finish

Run from the repository root (Git Bash or any POSIX shell):

```
bash tools/check-structure.sh
python -I tools/check-repo.py
python tools/lesson-decks/build_decks.py --check
```

[`check-structure.sh`](../tools/check-structure.sh) checks that the relative links in the hub pages resolve, that every lesson has an HTML twin, and that anchors into each background paper exist (units without a paper are reported as `NO BACKGROUND PAPER`). Fix every `MISSING`, `NO HTML TWIN` or `NOANCHOR` line. `check-repo.py` is the consistency check (Python compiles, lessons complete, course-map rows). The last command confirms the decks are up to date.
