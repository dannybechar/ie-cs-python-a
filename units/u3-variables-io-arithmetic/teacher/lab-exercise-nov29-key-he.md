5 משימות בקושי עולה, מכוונות ברמה גבוהה יותר מ-[`lessons/L02-from-input-to-result/lab-sheet-he.pdf`](../lessons/L02-from-input-to-result/lab-sheet-he.pdf) המאושר: אף משימה אינה חזרה ישירה על דוגמה שכבר נראתה מילה במילה במצגת. מתוכננות כך שתלמיד מתקשה יגיע ל-50 נקודות, ממוצע ל-75, מצטיין ל-95. הציון בפועל תלוי בכיתה; הטבלה למטה היא פרופיל מתוכנן, לא הבטחה.

## משימה 1 — ארבע הצצות לאותו מספר (הרצה, בינוני) · 20 נק׳

```python
a = 23
b = 4
print("Divide:", a / b)
print("Floor divide:", a // b)
print("Remainder:", a % b)
print("Check:", (a // b) * b + a % b)
```

מודפס: `Divide: 5.75`, `Floor divide: 5`, `Remainder: 3`, `Check: 23`. הסבר מצופה לשורה האחרונה: `a // b` נותן את מספר הקבוצות השלמות, `a % b` את מה שנשאר; כשמכפילים את מספר הקבוצות בגודל הקבוצה ומוסיפים את השארית, חוזרים בהכרח ל-`a` המקורי — זו הדרך לבדוק שהחלוקה "מתאזנת".

ניקוד: 12 נק׳ על ארבעת הפלטים הנכונים (3 נק׳ לכל שורה — הריצה עושה את העבודה, כך שזה אמור להיות נגיש לכולם), 8 נק׳ על ההסבר (הזהות הכללית, לא רק אימות עבור 23 ו-4).

## משימה 2 — ניחוש: הסיבוב של שלושה משתנים (הרצה, קשה) · 20 נק׳

```python
a = 5
b = 9
c = 14
a = b
b = c
c = a
print(a, b, c)
```

ניחוש שגוי נפוץ: `9 14 5` (כאילו התבצע סיבוב אמיתי). האמת: `9 14 9`. הסבר מצופה: בשורה `c = a`, המשתנה `a` כבר לא מחזיק את הערך המקורי 5 — הוא כבר הוחלף ל-9 בשורה `a = b`. אין שום "זיכרון" לערך הישן של `a` אלא אם שומרים אותו במפורש.

ניקוד: 10 נק׳ על הפלט הנכון אחרי הרצה (`9 14 9`), 10 נק׳ על ההסבר שמזהה במדויק איזו שורה "דורסת" את הערך הדרוש. זו הרחבה של הנקודה הרגישה בהחלפה הפשוטה (שני משתנים) לשלושה — קפיצת קושי מכוונת.

## משימה 3 — סיבוב אמיתי עם `temp` אחד (קוד, קשה) · 20 נק׳

```python
temp = a      # שומרים את הערך המקורי של a (5), לפני שהוא נדרס
a = b         # a = 9
b = c         # b = 14
c = temp      # c = 5 (הערך המקורי של a, ששמרנו)
print(a, b, c)     # 9 14 5
```

ניקוד: 12 נק׳ על קוד שעובד נכון עם משתנה עזר אחד בלבד (הסדר הקריטי: לשמור את `a` **לפני** ששורה כלשהי דורסת אותו), 8 נק׳ על פלט נכון `9 14 5` בהרצה בפועל. טעות נפוצה: לשמור `temp = c` במקום `temp = a` (שומרים את הערך הלא נכון); טעות נפוצה נוספת: להשתמש בשני משתנים נוספים במקום אחד (לא עומד בדרישה, אך אפשר לתת ניקוד חלקי אם הלוגיקה נכונה).

## משימה 4 — מחשבון טיול (קוד, קשה) · 20 נק׳

```python
students = int(input("Students: "))
price_per_student = float(input("Price per student: "))
bus_capacity = int(input("Bus capacity: "))

total_cost = students * price_per_student
full_buses = students // bus_capacity
students_left = students % bus_capacity

print("Total cost:", total_cost)
print("Full buses:", full_buses)
print("Students left over:", students_left)
```

עם 97, 42.5, 40: `Total cost: 4122.5`, `Full buses: 2`, `Students left over: 17`.

ניקוד: 10 נק׳ על שלוש שורות הקלט עם ההמרה הנכונה לכל אחת (`int` לשני המספרים השלמים, `float` למחיר), 10 נק׳ על שלוש שורות החישוב וההדפסה. טעויות נפוצות: `int` על המחיר העשרוני (`ValueError` עם `42.5`); שכחת ההמרה כלל (חיבור/הכפלה של טקסטים או `TypeError`).

## ★ משימה 5 — מוסיפים דמי ביטוח (קוד + הסבר, הכי קשה) · 20 נק׳

```python
insurance_fee = 7
total_cost = students * (price_per_student + insurance_fee)
```

עם 97 ו-42.5: `97 * (42.5 + 7)` = `97 * 49.5` = `4801.5`.

הטעות של החבר: `price_per_student + insurance_fee * students` מחשבת קודם `insurance_fee * students` (כי `*` קודמת ל-`+`), ואז מוסיפה את `price_per_student` **פעם אחת בלבד** — כלומר דמי הביטוח מוכפלים במספר התלמידים אבל מחיר הכרטיס מתווסף רק פעם אחת, במקום שניהם יחד יוכפלו במספר התלמידים. התוצאה השגויה: `42.5 + 7 * 97` = `42.5 + 679` = `721.5` — מספר קטן בהרבה מהתשובה הנכונה, ולא הגיוני (עלות כוללת קטנה ממחיר כרטיס בודד פלוס ביטוח לכולם).

ניקוד: 12 נק׳ על השורה המתוקנת והערך הנכון (`4801.5`), 8 נק׳ על ההסבר (מזהה את טעות הקדימות ונותן את הערך השגוי `721.5`). משימה למי שסיים — לא כולם יגיעו אליה בזמן, וזה בכוונה.
